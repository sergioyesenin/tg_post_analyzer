ID задачи
TASK-001

Название задачи
Унификация контракта конфигурации (env) и startup-проверки

Приоритет
Critical

Тип задачи
Architecture

Контекст проблемы
В коде используются DB_URL и APP_TZ, а в .env.example — DATABASE_URL и TZ. Это приводит к запуску с пустым DB_URL/неверным timezone при следовании документации. Ошибка проявляется на старте и в runtime-логике времени.

Цель задачи
Сделать единый, строгий и валидируемый контракт конфигурации.

Что нужно сделать
Привести имена env-переменных в коде и .env.example к одному набору.
Добавить startup-валидацию обязательных переменных (DB_URL, Telegram креды, auth secret и т.д.).
Добавить fail-fast с понятной ошибкой при неполной конфигурации.
Обновить места чтения timezone так, чтобы использовалось одно имя (APP_TZ или TZ), без двойной трактовки.
Технические требования
Нельзя оставлять “тихие” дефолты для критичных переменных подключения.
Ошибки валидации должны быть детерминированными и пригодными для логов.
Совместимость: допустить временный alias старых переменных на 1 релиз (опционально), с warning.
Ожидаемый результат
Запуск с некорректным .env невозможен; корректный .env.example реально запускает систему.

Критерии готовности (Definition of Done)
Все обязательные env проверяются при старте.
.env.example соответствует фактическому коду.
Есть тест/проверка конфигурации на startup path.
Нет мест, где используются конфликтующие имена переменных.
Зависимости
Нет
Блокирует
TASK-002, TASK-003, TASK-005, TASK-010
Возможные риски
Ломка локальных окружений у команды из-за переименования env.
Неполный список обязательных параметров.
Что передать в новый чат с Codex
Цель: унифицировать env-контракт и добавить fail-fast валидацию при старте.
Контекст: сейчас конфликт DB_URL/APP_TZ vs DATABASE_URL/TZ.
Ожидаемый результат: единый набор env, startup падает с понятной ошибкой при неполной конфигурации.
Ограничения: не вводить silent fallback для критичных переменных.
Проверить перед изменениями: config.py, .env.example, места вызова settings.
Если не хватает контекста: запросить точный runtime entrypoint(ы), где выполнять startup validation.

Технические требования
